00v3 Corrections (3 architectural changes)

v2 was honest about being a framework but wrong about the building blocks

# v2 Problem v3 Fix
1 Logger: 108-line custom slog handler with manual isTerminal detection Replace with charmbracelet/log. charmlog.New(slog.LevelInfo) → slog.NewHandler() → slog.New(handler). ~5 lines instead of 108. Pretty colored TTY output, JSON mode, level control — all built in. cmdguard already has LogLevel.SlogLevel() for the same conversion. 4 other ecosystem projects use charmbracelet/log.
2 SQLite: 111-line OpenSQLite with manual PRAGMA allowlist. Plain *sql.DB, no event store, no CQRS Replace with go-cqrs-lite/stack/sqlite. stack/sqlite.New(dsn) → *stack.Bundle with: event store (EventSink+EventSource), command store, query store, snapshot store, checkpoint store, KV read models, in-process bus, auto schema migration, WAL mode, busy timeout — all handled. appkit's Service.Bundle exposes the full CQRS/ES stack.
3 Named "skeleton" — dishonest. A skeleton is scaffolding you modify. This is a framework you build on top of Renamed to "framework" everywhere. File renamed: path2-superb-service-framework.html. All copy updated. Honest about being opinionated with non-removable defaults and a blocking Run().
4 No Huma integration story. Plan ignored the most popular type-safe API framework in the Go ecosystem Document the Huma pattern (not a dependency). httputil already proved the pattern: Huma wraps svc.Mux INSIDE via humago.New(mux, config), httputil middleware wraps OUTSIDE via httputil.Chain. The layers never collide. appkit documents this in README — the consumer optionally wraps svc.Mux with humago for typed APIs + OpenAPI 3.1 generation. Zero dependency cost — Huma is a user of the mux, not a dep of appkit.
5 Treated go-error-family as sentinel registration — the escape hatch, not the model Proper 3-layer adoption. Layer 1: replace fmt.Errorf + sentinels with constructors (NewRejection, WrapTransient) — appkit's errors ARE classified at construction, not retroactively. Layer 2: use boundary terminators — HTTPHandler for error responses, LogError for shutdown logging. Layer 3: bridge/oops is application-only — appkit as a library does NOT import it. Classifiers only for third-party errors (*sqlite.Error).
Architecture impact: appkit's dependency tree grows from 1 (sqlite) to 4 same-ecosystem libraries. But the value proposition transforms from "5 helpers" to "import one package, get a full CQRS service with pretty logging, HTTP middleware, health, and graceful shutdown." The dependency cost is real but bounded — all deps are same-author, zero-transitive-bloat.

01Why appkit Exists

The question

If httputil has HTTP, go-cqrs-lite has CQRS/ES, charmbracelet/log has logging, and go-error-family has errors — why does appkit exist?

Answer: composition is the value

None of those libraries compose themselves. httputil is HTTP-only (depguard-enforced: $gostd + error-family). go-cqrs-lite/stack is a CQRS engine with no HTTP or signal handling. charmbracelet/log is a log formatter with no service lifecycle. appkit is the composition root — the one import that wires them together into a running service.

Composition map ├─ appkit (FRAMEWORK) ← THE composition root │ ├─ httputil Server, Middleware (Recovery/ReqID/Log/Timeout/Sec), Health │ ├─ go-cqrs-lite/stack Bundle: EventStore, CommandStore, QueryStore, Bus, Snapshots, KV │ ├─ charmbracelet/log Pretty slog handler (colored TTY, JSON, levels) │ └─ go-error-family Error classification (Rejection/Conflict/Transient/Infrastructure) ├─ Application (main) Imports appkit, registers routes + CQRS handlers, calls svc.Run(ctx) └─ Go stdlib net/http, log/slog, os/signal

03Design Decisions

Decision 1

Service owns the mux AND the Bundle

Yes. Service creates *http.ServeMux and calls stack/sqlite.New(dsn) internally. Exposed via svc.Mux and svc.Bundle. Consumer registers routes and CQRS handlers on them. If the consumer created them, they'd have to wire health, middleware, and bundle lifecycle themselves — defeating the purpose.

Decision 2

Run(ctx) blocks and handles signals

Yes. Run(ctx) = start server → wait for SIGINT/SIGTERM or ctx.Done() → shutdown server + bundle → return. This is the main() terminator. Start() <-chan error remains for non-blocking use.

Decision 3

SQLite via cqrs-lite/stack, not bare database/sql

Yes. ServiceConfig.SQLitePath triggers stack/sqlite.New(dsn). The consumer gets a *stack.Bundle with event store, command store, query store, bus, snapshots, KV — auto-migrated, WAL-enabled. The raw *sql.DB is accessible via svc.Bundle.Database().(*sql.DB) for direct queries. If path is empty, no bundle is created (stateless service).

Decision 4

Middleware extendable, not replaceable

Extendable only. Default stack (Recovery → RequestID → Logging → Timeout → SecurityHeaders) always runs. cfg.ExtraMiddlewares to add. If a consumer needs a different base stack, they use httputil directly.

Decision 5

Logger via charmbracelet/log, not custom slog handler

Yes. InitLogger creates a charmbracelet/log logger, wraps it as a slog.Handler via log.NewHandler(), returns slog.New(handler). ~5 lines replaces 108. Pretty colored TTY by default, JSON on demand. Aligns with cmdguard's LogLevel.SlogLevel() pattern.

04aHuma Integration (documented, not depended on)

Huma and appkit are complementary layers, not competing

Huma operates inside the mux (typed operations, validation, OpenAPI). appkit/httputil operate outside (middleware, lifecycle, health, DB). Same pattern httputil already documented and proved.

Request flow with Huma Client → httputil.Chain (Recovery → ReqID → Logging → Timeout → Sec) → svc.Mux (*http.ServeMux) → humago adapter → huma operation handler (typed input → validation → OpenAPI) → OR: plain http.HandleFunc (no Huma needed)
appkit's role: expose svc.Mux. The consumer wraps it with humago.New(svc.Mux, huma.DefaultConfig("My API", "1.0.0")) for type-safe APIs + auto-generated OpenAPI + JSON Schema. Or uses plain svc.Mux.HandleFunc. appkit stays out of it. Zero dependency on Huma. 
// Plain mux path (default)
svc.Mux.HandleFunc("GET /users/{id}", handler)
// Huma path (consumer opt-in)
api := humago.New(svc.Mux, huma.DefaultConfig(
    "My API", "1.0.0"))
huma.Get(api, "/users/{id}", typedHandler)

07Before / After

Before (today — ~50 lines, no middleware, no CQRS)
After (framework — ~15 lines, full CQRS service)
// Today: 50+ lines, no middleware, no CQRS
func main() {
    logger, _ := appkit.InitLogger(appkit.LoggerConfig{})
    db, _ := appkit.OpenSQLite(ctx, appkit.SQLiteConfig{
        Path: "app.db",
    })
    mux := http.NewServeMux()
    // no middleware at all
    srv := appkit.NewServer(cfg, mux)
    go srv.Start(ctx)
    appkit.WaitForSignal(ctx, cfg, func(sctx) error {
        srv.Shutdown(sctx)
        db.Close()
        return nil
    })
}
// Framework: 15 lines, full CQRS service
func main() {
    svc, err := appkit.NewService(appkit.ServiceConfig{
        Addr:       ":8080",
        SQLitePath: "app.db",
        LogLevel:   appkit.LogLevelInfo,
    })
    if err != nil { log.Fatal(err) }
    defer svc.Close()

    // CQRS bundle + middleware already wired
    repo, _ := stack.Repository[MyState](
        svc.Bundle, myDecider,
    )
    svc.Mux.HandleFunc("POST /commands",
        makeHandler(repo))

    if err := svc.Run(ctx); err != nil {
        log.Fatal(err)
    }
}

14Graceful Degradation

S1

DB unreachable at startup

Hard fail. stack/sqlite.New returns error. NewService returns error. Service never starts. Classified as Infrastructure.

S2

DB drops at runtime

Ready-probe fails. Consumer wires ReadyHandlerWithProbe(db.Ping). Kubernetes routes traffic away. Server stays up.

S3

No DB configured

Stateless service. SQLitePath="". svc.Bundle is nil. Health returns 200. Valid for stateless services.

16Risks

R1

httputil.Server.Addr() returns string

appkit owns net.Listener to preserve Addr() net.Addr for :0 tests.

R2

go-cqrs-lite/stack pulls many modules

stack/sqlite depends on event/v3, command/v3, query/v3, codec, storage/sql, watermill, etc. This is the heaviest dep. Mitigation: all same-author, all tested, all modular. The value (full CQRS/ES) justifies the dep tree.

R3

httputil.Server has zero real consumers

cqrs-htmx uses only ClientIP. Mitigation: If Server proves problematic, appkit falls back to owning http.Server directly while keeping httputil middleware + health.
