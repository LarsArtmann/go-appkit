Pareto Plan

Path 2: Make go-appkit a Superb Service Skeleton

From "5 random helpers nobody should import" to "production-ready Go service in 15 lines." This plan transforms go-appkit into the one-import skeleton that wires server + middleware + health + logging + DB + shutdown with opinionated defaults.

00The Vision

The Problem Today

go-appkit provides ~150 lines of value spread across 5 files, of which 60% duplicate httputil. No consumer should import it. It's "too big to be a copypaste snippet, too small to justify an import, too overlapping with httputil to have a defensible niche."

The Solution: The Service Type

A single Service type + NewService(cfg) + svc.Run(ctx) that gives you a production-ready HTTP service in 15 lines. It composes httputil (server + middleware + health), keeps appkit's unique logger/sqlite/shutdown, adopts go-error-family for classified errors, and orchestrates graceful shutdown.

Before (today — ~40 lines of wiring)
After (Path 2 — ~15 lines)
// Today: consumer wires everything
func main() {
    logger, _ := appkit.InitLogger(appkit.LoggerConfig{})
    db, _ := appkit.OpenSQLite(ctx, appkit.SQLiteConfig{Path: "app.db"})
    mux := http.NewServeMux()
    srv := appkit.NewServer(appkit.DefaultServerConfig(), mux)
    go srv.Start(ctx)
    // no middleware, no recovery, no request-id
    // manually wire signal handling
    appkit.WaitForSignal(ctx, cfg, func(ctx) error {
        srv.Shutdown(ctx)
        db.Close()
        return nil
    })
}
// Path 2: appkit does it all
func main() {
    svc, err := appkit.NewService(appkit.ServiceConfig{
        Port:       8080,
        SQLitePath: "app.db",
        LogLevel:   appkit.LogLevelInfo,
    })
    if err != nil { log.Fatal(err) }
    defer svc.Close()

    // recovery, request-id, logging, timeout already wired
    svc.Mux.HandleFunc("GET /", handler)

    // serves until signal, then graceful shutdown
    svc.Run(ctx)
}

Tier 1 — The 1% that delivers 51%

The Service type + NewService + Run. One type, one constructor, one method. Even with internals still duplicating httputil underneath, this alone transforms the value proposition from "helpers" to "skeleton." The identity change happens here.

Tier 2 — The 4% that delivers 64%

httputil delegation + default middleware stack. Stop duplicating server.go/health.go. Wire Recovery → RequestID → Logging → Timeout → SecurityHeaders as defaults. Now it's not just a convenience wrapper — it's a production convenience wrapper with the middlewares consumers always forget.

Tier 3 — The 20% that delivers 80%

Graceful shutdown orchestration + error-family adoption + config validation. Signal → server.Shutdown → db.Close with timeout. Classify SQLite/listen/PRAGMA errors. Validate configs at startup. These are the things that make "production-ready" an honest claim.

Tier 4 — Polish to 100%

README, example, tests, docs, optional extras. The "production-ready in 15 lines" pitch. A runnable example. Full test suite. Updated AGENTS.md. Optional: Postgres, /metrics, env-config.

06Risks & Tradeoffs

Breaking Change

Existing consumers of NewServer / ServerConfig

server.go — public API

Delegating to httputil may change Start/Shutdown signatures. Existing consumers must adapt.

Mitigation: Keep the old API as a thin adapter. Server wraps httputil.Server, same method names. Or bump major version (v2).
Dependency Scope

Adding httputil + go-error-family

go.mod

appkit currently has one dep (sqlite). Adding httputil (+ its sole dep go-error-family) is minimal but changes the "zero-dep" perception.

Mitigation: go-error-family has zero transitive deps. httputil's only dep IS go-error-family. Total new deps: 2 libraries, zero transitive bloat. This is acceptable for a "production-ready skeleton."
Design Decision

Opinionated defaults vs flexibility

ServiceConfig design

Path 2 is explicitly opinionated. Consumers who disagree with the middleware stack or health endpoints can use httputil directly. appkit is for the 80% who want sane defaults.

Key principle: Every default must be overridable. ServiceConfig exposes every knob. The opinionated default is a starting point, not a cage. ExtraMiddlewares lets consumers add without replacing.
