go-appkit adoption: the 28-review fleet verdict

Every consumer repo carries a docs/review/libs/go-appkit.md. All 28 were read in full — 23 by four parallel readers, five that landed mid-review by a fifth. This report is the resulting adoption picture: who adopted and how deep, who is one trigger away, what blocks the rest, and what would convert them.

00Summary

Adoption is real but shallow, and the shape is consistent. Seven projects adopted the core — spanning every score band (cqrs-htmx 100/100, Code-To-CV-Agent 90/100, pbx-lens 73/100, media-atlas 61/100, index 53/100, quotaboard 50/100, PapDashboard 31/100). Nine more declined the framework but named a concrete module, trigger, or “next service” condition. The flat declines are fit- and dependency-based, never doc-based: the corpus records “rejection is fit, not quality” as the standard decline — which is the best possible kind. The two levers that would move the most: kill the released-vs-pinned drift tax (it burned four audits and physically blocked PapDashboard from deleting ~400 lines of hand-rolled security code), and make the submodule ecosystem visible to people who already adopted the core — the single most repeated failure in the corpus.

The bottom line go-appkit wins every evaluation it is qualified for and loses only on fit or dependency doctrine — exactly what a framework wants. The growth is not in converting decliners; it is in deepening the seven adopters (median score 61 means the core is used and the ecosystem is not) and in owning the greenfield lane that seven separate decliners already point at.

◆What converts (keep doing this)

+
The one-line positioning statement does all triage “Production-ready HTTP service framework for Go” is quoted back, verified with head -20 README.md, and produces instant clean verdicts in both directions — fast interest and reputation-positive “fit, not quality” skips. No review misread what appkit is.
+
Responsive gap-closure converts skeptics The strongest trust event in the corpus: cvagent flagged three gaps on 2026-11-04, all shipped by the 2026-11-05 bump wave, score 75→90. cqrs-htmx’s “no expansion” verdict exists because the hook forwarding gap landed. Agents audit repeatedly and reward exactly this.
+
Per-module independence keeps rejected consumers warm Most declines name a first module with a trigger and a recipe (“each can be judged alone when its trigger fires”). The module table in the README is the artifact those disposition maps are built from.
+
The CHANGELOG is the agent planning API pbx-lens planned and executed a three-minor bump from CHANGELOG entries alone (“SSE/NoTimeout-safe per the v0.10.0 entry”); index cites it by line number; the [Unreleased] section is tracked as a flip-trigger. This is the single highest-leverage doc artifact in the corpus.
+
Quantified DX wins sell better than features “5s → 0.81s” (pbx-lens testkit) and “exactly as designed” are the corpus’s full-adoption proof points. Both are measurable, both shipped in the library.
+
Line-citable docs survive hostile audits audiblesync ran a complete overlap audit from README line ranges alone (drain phases 246–280, NoTimeout sentinel 321–337, sd_notify contract :75, license 375–378) — zero source reads needed. That is the docs-as-spec gold standard, and it shows up as trust in the verdict text.

02What blocks deeper adoption

Ordered by adoption impact. Each finding is a pattern the corpus demonstrates more than once, with the fixing lever named.

Adoption blocker · High impact

1. The released-vs-pinned drift tax burned four audits and blocked one adoption outright

quotaboard · ChastityAPI · PapDashboard · webphone · io-surface

quotaboard: “ServerTiming *bool (field does not exist at the pinned v0.9.0; the dev checkout’s default-on stack is unreleased).” ChastityAPI validated against “upstream’s unreleased default-stack change.” PapDashboard could not adopt security/ at all because “submodule features still arrive in master only” — so it kept ~400 lines of hand-rolled security middleware. webphone’s prior ruling went stale because “the inventory drifts in days, not quarters.” io-surface reconstructed shipped-vs-unreleased itself. Three more reviews needed mid-audit refresh banners when a new tag landed mid-read.

Fix Tag all modules in lockstep with the trains (the wave pattern already exists), keep the [Unreleased] separation loud, and publish a machine-checkable module→newest-tag inventory — the artifact webphone asked for by name.
Utilization blocker · High impact

2. Adopters use the core and never discover the ecosystem

PapDashboard (31/100) · index (53/100) · quotaboard (50/100) · media-atlas (61/100) · cqrs-htmx (100/100 core, 0/12 submodules)

The most repeated failure in the corpus. PapDashboard: “core shell at 100%; the fleet modules at 0% — several deliberately… several by drift,” with ~400 lines of security middleware a submodule would delete. index hand-rolled CSP/nonce logic while security.GenerateNonce sat at its pin — “pure deletion opportunity.” quotaboard reads config at a third of its depth. media-atlas lists the same one-line wins (RegisterClassifications, testkit) audit after audit, undone. Adoption of the core does not create awareness of submodules; only a full capability audit surfaces the duplication, and most consumers never run one.

Fix A per-capability adoption page and a “replace your hand-rolled X with one line” quickstart — the highest-conversion pitch the corpus knows, currently absent. Name the replacement target on every module row.
Adoption blocker · High impact

3. Opinionated and hidden dependency contracts veto adoption from outside the docs

dnsblockd (go.mod:6, logger.go) · go-taskqueue (go.mod grep) · ChastityAPI (HealthRecorder interface) · CV (donor overlap)

The decisive facts in four declines live in go.mod or source, not any README: dnsblockd’s blocker is the charmbracelet/log-vs-slog doctrine (“no slog adapter and no pluggable log backend” across three checked releases); go-taskqueue’s keep-out is the transitive httputil requirement its own ADR forbids; ChastityAPI discovered only in code that flightrecorderhealth.Trigger forces samber/do — “the interface forces samber/do” killed the module. Consumers audit dep surface; docs that pre-state it (“root-free: deps…” got verified and praised in dnsblockd’s httpx note) turn a veto into a two-minute correct decline.

Fix README front page states the opinionated core deps and each module’s dep surface; flag any interface that forces a third-party container up front.
Conversion blocker · Medium impact

4. No roadmap/limits page, so reviewer blocker-lists calcify

nsfw-classifier (4 blockers, all “Stand”) · dnsblockd (flip trigger)

nsfw-classifier re-verified nine days later and all four blockers “Stand” — listener injection (“grep WithListener: zero hits”), error-model divergence, metrics posture, logger major-behind. go-compliance lands on the same missing seam from the other side: “appkit core binds TCP only” against its load-bearing unix-socket bind. Two consumers, one absent capability, zero upstream position. Nothing states a stance on any of these, so verdicts can only flip when a reviewer happens to re-sweep. The corpus also proves the converse: cvagent’s gaps shipped within a day and the score moved 75→90. Responding converts; silence calcifies.

Fix A public ROADMAP/limits doc with a position per known blocker (planned, declined-with-reason, or accepted). A recorded NOT-DO converts a permanent keep-out into an informed one.
Trust blocker · Medium impact

5. Release velocity reads as churn without stability framing

go-taskqueue · Cyberdom · dnsblockd (tag tooling)

go-taskqueue: “the 3-day tag cadence + same-day major retirement is churn, not maturity,” plus “v4 had been uninstallable via go get since v4.2.1” found while the README advertised v4. Cyberdom: “most submodules are v0.1–v0.2 with tags landing daily… N pins to track and N vendorHash bumps.” Yet google-domain-detector read the same activity as “actively maintained” — framing decides. And the multi-module tag scheme silently breaks naive latest-version tooling (dnsblockd’s git tag | sort -V | tail -1 returned docs/v0.3.1).

Fix Document the tagging scheme (root vs prefixed tags, how to compute newest per module), and add a short stability story next to the velocity numbers: what a minor promises, what the floor policy is, why waves are safe to pin.
Funnel · Medium impact

6. Seven decliners independently point at the same conversion condition — the greenfield lane — and no doc owns it

browser-history · invoices · profileagent · audiblesync · journal · offline-banner · nextd

browser-history: “A greenfield sibling should start there” (preset/config/httpx). invoices: “any NEW service in the larsartmann fleet should start from go-appkit.” profileagent’s trigger is a future service binary with the EventService recipe as skeleton. audiblesync watches systemd for “ROADMAP theme 3.” journal keeps appkit as the alternative at the T23 decision point. offline-banner’s trigger is “a Go application joins the fleet → the appkit preset spine is the obvious host”; nextd’s is “a sibling web service materializes.” The conversion condition is identical — the next new service — and it is currently recorded only inside each consumer’s private review.

Fix Own the lane explicitly: a “start your next service here” preset-first page with the two or three named recipes (NewService spine, EventService skeleton, httpx handler) and a go-template / scaffold to make the first hour mechanical.
Utilization · Low impact

7. Boot-required calls are invisible to quickstarts, and docs churn breaks verification needles

Code-To-CV-Agent (RegisterClassifications) · CV (FEATURES needle)

cvagent’s one remaining red row is RegisterClassifications() — “one idempotent boot line,” never called, found only by the auditor’s rg. Quickstarts show the happy path, not the complete must-call set. Separately, CV’s standing audit needle (“ported from CV”) “died in the sibling’s FEATURES restructure” — machine-checkable provenance claims need stable anchors or announced migrations.

Fix Quickstart lists the full boot set (including optional-but-recommended lines); treat doc headings as API — announce restructures in the CHANGELOG.
