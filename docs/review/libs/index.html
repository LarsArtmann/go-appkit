00Summary

Three of the twelve sibling libraries are imported — httputil (the middleware/health substrate of core), go-error-family (the repo-wide error protocol), and go-sse (the realtime transport). All three sit at the newest published tag. The other nine are not used, and none of the non-uses is neglect: each one is either an intentional indirect (go-etag, go-idempotency, go-retry, go-codec ride the graph through httputil and go-cqrs-lite), a pre-named battery floor (go-atomic-write for D4, server_timing for F2), or a researched category mismatch (go-daemon, go-output, go-filewatcher).

The audit's real yield is small and precise: utilization is deep but not maximal in the three adopted libraries, and the gaps split into one actionable refactor (appkit/otel's custom Recovery predates httputil v1.6.0's RecoveryWithConfig/OnPanic hook it was designed for), one structural half-adoption (go-error-family's classification registry is never used), and a handful of demand-gated battery candidates that are already on the books.

The bottom line Adoption posture: exemplary — every use and every non-use carries a recorded rationale, and version currency is perfect. Utilization: 72/100 (httputil), 81/100 (go-sse), 46/100 (go-error-family). The cheapest real improvement is delegating appkit/otel's custom Recovery middleware to the httputil hook that shipped for exactly this purpose; the structural one is deciding, once, whether a fleet-default error-classification registry should exist.
OWNER RULING · 2026-11-03 (post-publication errata) The owner clarified the repo's mission: go-appkit exists so his apps can smartly compose the family's libraries — demand-gating a FAMILY lib out of the framework contradicts the reason it exists. Consequence #1 shipped the same day: servertiming.ServerTimingMiddleware() (httputil/server_timing v1.0.3, direct require) is now OUTERMOST in core's default stack. Consequence #2: W3-httpx B5 content negotiation on go-codec is promoted to in-scope. Dated errata blocks live in server_timing.md and go-codec.md; the go-etag / go-idempotency / go-retry reports already frame non-use as recorded adoption paths and need no errata. NOT flipped: go-daemon, go-output, go-filewatcher (category mismatches, not demand questions).

02Findings

Ordered by impact. Only F1 changes code.

Important · Medium impact · code

F1 — appkit/otel's custom Recovery predates the httputil hook built for it

otel/exceptions.go:19-37 · httputil v1.6.0 shipped RecoveryWithConfig/OnPanic on 2026-10-24; otel's middleware predates it

appkitotel.Recovery hand-replicates httputil.Recovery's behavior (log-line contract, ErrAbortHandler re-panic) plus OTel exception-span capture. httputil v1.6.0 now exposes RecoveryWithConfig with an OnPanic hook for exactly this integration. Delegating deletes the behavioral duplication surface while keeping the OTel payload; the existing exceptions tests pin the contract.

Fix Refactor appkitotel.Recovery to httputil.RecoveryWithConfig + an OnPanic hook that records the exception event. Cheap, testable — the one actionable code finding of this audit. Verified unused: rg 'RecoveryWithConfig|OnPanic' otel/ is empty.
Important · structural · demand-gated

F2 — go-error-family's classification registry is never used

zero calls to Classify / RegisterClassification / RegisterStdlibDefaults across all 12 modules

Appkit classifies at creation (wrap-at-source) but never at boundaries that receive FOREIGN errors: third-party probe errors in health, arbitrary handler errors rendered by errorpages (unclassified → 500 by contract), MaxBytesError handling in security. A single fleet-default classification registration (stdlib defaults + http.MaxBytesError → Rejection + context.Canceled → Infrastructure) would make Classify meaningful there and centralize per-module ad-hoc mapping. Additions-only; gate on a real misclassification incident or consumer ask.

Nice to have · battery candidates (already demand-gated)

F3 — three httputil families with no adoption story yet

CORS (zero usage), ClientIP/trusted-proxy keying (v1.6.0, unused), Compression/Decompression (zero usage)

security/origin_check.go is CSRF origin validation, NOT resource-sharing CORS — a browser-API consumer on appkit has no CORS story today. Rate limiting keys on RemoteAddr; KeyExtractorFromTrustedClientIP solves the behind-a-proxy deployment and is unused. These belong on the W3/W4 battery shortlists, not in the default stack.

Nice to have · documentation & upstream watch

F4 — truth-sync items surfaced by the audit

AGENTS.md:65,67 · TODO_LIST battery rows · upstream [Unreleased] sections

(a) AGENTS' Core Dependencies table said httputil v1.4.0 / error-family v0.10.1 vs go.mod v1.7.0 / v0.12.0 — fixed in this audit. (b) Battery B4's go-etag note should mention the five-module split (client + metrics are relevant to W4's polite client). (c) go-sse's next release carries a breaking ssetest.WithLastEventID signature change and an exported DefaultSubscriberBuffer that realtime's doc comment cites as unexported — absorb at the next re-pin, not before.
