# Agent Notes: go-appkit

Production-ready HTTP service framework composing httputil, charmbracelet/log, and go-error-family.

## Project Type

- Go multi-module repository (`github.com/larsartmann/go-appkit`), Go 1.27.3 (1.27.1 unified 2026-09-29; 1.27.2 floor train 2026-10-12 — cqrs-htmx v4.14.0 requires ≥1.27.2, clears GO-2026-6617; 1.27.3 floor train 2026-11-07 — clears stdlib GO-2026-6809 crypto/x509).
- Fifteen Go modules in one repo, independently versioned (fourteen released + one unreleased: the `integration` test module, never released by charter). Per-module release history lives in the module CHANGELOGs; per-module code organization, dependency tables, and gotchas live in `docs/agents/module-details.md` — read a module's section there before changing it:
  - **core** (`/`) — package `appkit`, HTTP service framework: `Service` lifecycle (Start/Drain/Shutdown hooks, `StartHooks` post-listen seam since v0.8.0), middleware stack (Server-Timing outermost since v0.10.0), opt-in metrics/version/testkit (`testkit.NewService` test-safe defaults since v0.9.0; `FreeAddr`/`WaitForRunning`/context-GET helpers since v0.10.0), `RegisterClassifications()` fleet-default error registry since v0.10.0 (idempotent, deliberately not auto-called).
  - **cqrs** (`/cqrs`) — package `cqrs`, CQRS/ES integration over go-cqrs-lite's `system` engine: typed command/query facade, projections, DLQ, `EventConfig.Domain` passthrough (v0.7.0).
  - **realtime** (`/realtime`) — package `realtime`, SSE transport layer built on go-sse (hub + canonical endpoint + replay). SSE only — no WebSocket.
  - **security** (`/security`) — package `security`, opt-in HTTP security batteries ported from CV per the canonical battery spec (W2): API-key auth, CSRF, keyed rate limits, origin check, body limit, sanitization, CSP nonce/policy. ALL opt-in — nothing joins the default stack. See `security/THREAT_MODEL.md`.
  - **otel** (`/otel`) — package `otel` (alias `appkitotel`), OpenTelemetry provider setup + otelhttp middleware bridge + trace-correlated logging; v0.2.0 added SigNoz-grade OTLP, exception capture, an importable dashboard, and the flight-recorder metric bridge; v0.3.0 (2026-10-18, SUPERB v8) added SDK self-diagnostics through slog, the `Transport()` client-span wrapper, process-identity resource detectors, the exporter off-switch, and baggage correlation helpers.   - **flightrecorder** (`/flightrecorder`) — package `flightrecorder`, HTTP middleware for Go runtime trace capture (async initiation since v0.2.0; requires go-flightrecorder v0.2.1+ — v0.2.0 raced Reset vs async captures).
  - **flightrecorderhealth** (`/flightrecorderhealth`) — package `flightrecorderhealth`, bridges go-flightrecorder with go-health: dashboard visibility + auto-capture on health failures.
  - **health** (`/health`) — package `health` (alias `appkithealth`), bridges go-health probes + go-health-dashboard real-time UI into appkit services.
  - **httpx** (`/httpx`) — package `httpx`, the handler-DX battery (W3; v0.1.0 = B1/B2/B9, v0.2.0 = B3/B4/B5/B7): `ResultHandler` return-(T, error) seam, `ResultHandlerWithValidation` bind battery (`bind.*` Rejection codes, tagged-adapter + snake_case-wire stance), `WriteError`/`SanitizeErrorMessage` classified no-leak error contract, the test-pinned classification-parity oracle vs errorpages (one taxonomy, two renderings; test-only dep), `WrapWriter`+`httpxtest` forwarding probe (B3), `Conditional` on go-etag/server + IMS precedence (B4), `Negotiate`/`RequestCodec`/`ResponseCodec` on go-codec (B5), `WriteDeadline` per-route deadlines (B7). ## Architecture and Control Flow

- `Service` owns the mux (`svc.Mux`), logger (`svc.Logger`), and HTTP server.
- Consumer registers routes on `svc.Mux`, then calls `svc.Run(ctx)` which blocks.
- appkit DOES delegate the server loop to `httputil.Server` since the 2026-11-07 composition swap: `Start()` binds + classifies `listen_failed` synchronously, constructs `httputil.NewServerListener` BEFORE the hooks (pure; upstream rejections surface as `server.config_invalid` Rejections pre-lifecycle), and delegates only serve/shutdown ownership — fresh `httputil.Server` per Start (upstream single-serve ownership; restart-after-full-shutdown now serves again, pinned in delegatedserver_test.go). `Addr()`/`Running()` stay appkit's mutex-guarded `s.ln` view; the six phase lines + `server.shutdown_failed` classification stay appkit-side; `ServerConfig.ShutdownTimeout` = the SAME `ServiceConfig.ShutdownTimeout` field (deadline-less `Close()` inherits that bound — deliberate single-source). Full mapping + the G1 TLS sketch: spike doc §5-§6 (`docs/planning/2026-09-16_composition-spike-verdict.md`).
- httputil is used for: middleware (`Chain`, `Recovery`, `Logging`, etc.), health (`RegisterHealth`), and types (`Middleware`).
- `ServiceConfig.RegisterHealth` is `*bool`: nil or `&true` = register health, `&false` = opt out.
- Graceful drain: `Shutdown()` flips `readyProbe` to false → runs `DrainHooks` (external readiness signals flip in lockstep; errors joined, classified Infrastructure) → waits `DrainDelay` → `server.Shutdown(ctx)` → runs `ShutdownHooks` (once, in order; failures don't stop the rest; errors joined + classified Infrastructure).
- `Run()` uses `signal.NotifyContext` for SIGINT/SIGTERM internally.
- Errors use go-error-family constructors (`NewRejection`, `WrapInfrastructuref`) instead of `fmt.Errorf`.

## Release Ritual (added 2026-09-04, extended 2026-09-17)

1. **API-break check before every tag:** `git archive <old-tag> | tar -x -C /tmp/old && GOWORK=off GOTOOLCHAIN=go1.27.3 go doc -all . > /tmp/new.txt` (old from the extracted dir, new from the working tree), then diff — additions only → minor bump; ANY removal or signature change → breaking (0.x: minor bump + migration notes in CHANGELOG). Proven during wave 2 (core v0.3.0 → v0.4.0). `goapidiff`/`apidiff` not installed; `go install @latest` is network-blocked in this environment.
2. Date the module's CHANGELOG `[Unreleased]` → `[version] - <date>`, then hermetic-verify (`GOWORK=off`; jsonv2 only where the toolchain still needs it); fresh-consumer proxy test after push per `docs/recipes/fresh-consumer-proxy-check.md`.
3. **Same-train release-state updates:** update AGENTS `_Release State_` + the module's bullet + the TODO_LIST header + **FEATURES.md** (version-truth + new rows — the 09-29 otel train shipped while FEATURES still listed the old surface) in the same train as the CHANGELOG dating, then run `./scripts/check-pin-drift.sh` (and `check-go-directives.sh` while the unification train is open) — both must be green before push (v0.5.1 shipped while AGENTS still said v0.5.0; this step makes that class impossible to repeat silently).
4. **Tidying integration against a not-yet-pushed tag (2026-10-06, cqrs v0.7.0):** the fleet is GOPRIVATE, so `go mod tidy` resolves tags via VCS (`git ls-remote origin`), not any GOPROXY — a fresh local tag cannot be tidied against until pushed. Trick: `git config --global url."/home/lars/projects/go-appkit".insteadOf "https://github.com/larsartmann/go-appkit"` makes the VCS resolution hit the LOCAL repo (sees the tag, builds the CANONICAL zip — go.sum hashes match what consumers get), run tidy + suite, then `--unset` the rewrite. Do NOT hand-craft module zips into the download cache — non-canonical zips poison go.sum. GOSUMDB must stay ON for toolchain downloads (off breaks toolchain verification); network to GitHub + sumdb works here.
5. **Gate before every push:** `git tag -a <tag> -m "<semantic delta>" … && ./scripts/pre-tag-checks.sh <tag> && git push origin master <tag>` — annotated tags only, message states the semantic delta (`docs:` prefix for doc-only releases, v0.5.1 convention); the script re-runs the twelve standing guards (directives, pin-drift, dependabot parity, workspace charter, routed-destinations, golangci-configs, consumer claims, sse-protocol, gosum-canonical, art-dupl — gosum-canonical resolves every module's deps through an isolated cache against proxy+sumdb: the 2026-10-14 pre-re-tag-hash class, slow, network; routed-destinations added 2026-11-02/SUPERB v10 fails on any dead `→ routed` pointer in the living docs, golangci-configs joined the same day so schema drift cannot ship in a tag either) AND asserts the TAGGED artifact's go.mod (floor-exact directive, no toolchain line, no filesystem replace); it fails on `flightrecorderhealth/v0.1.4` by design (the tag that shipped `go 1.27`, caught 2h late in 2026-09-29). Multi-tag waves (2026-10-12): pass every tag of the wave — `./scripts/pre-tag-checks.sh v0.9.0 health/v0.2.0` runs the guards ONCE, asserts every tagged artifact, then `git push origin master v0.9.0 health/v0.2.0`.
6. **Release ordering when integration already pins the module (2026-11-06, health v0.3.1):** the gate is structurally unsatisfiable BEFORE the push — `check-pin-drift` demands integration's pin equal the NEWEST LOCAL tag while `check-gosum-canonical` demands every pin resolve through the public proxy, and a brand-new tag is not on the proxy yet (the integration leg dies `unknown revision`).
