# i18n for go-appkit — research + module sketch

Date: 2026-10-09 · Status: RESEARCHED, not adopted · Demand gate: P3 (TODO_LIST)

**Question.** How do we help appkit consumers with i18n "and co" (locale
negotiation, message lookup, hreflang/SEO, formats)? Sources: the proven T49
implementation in `~/projects/sperrmuell-direct` (bilingual DE/EN customer
funnel, shipped 2026-10-08) + ecosystem research (go-i18n, golang.org/x/text,
SEO guidance).

## Verdict

Build an opt-in 13th module **`go-appkit/i18n`** that extracts the T49
pattern — but only when demand appears (today N=1 consumer). The extraction
is small (~250 LOC + tests) because the pattern is battle-proven; the one
place the consumer implementation is genuinely weak (hand-rolled
Accept-Language parsing) is exactly where the framework version must upgrade
to `golang.org/x/text/language.Matcher`.

## What sperrmuell-direct T49 proves (the pattern inventory)

| Concern | Implementation (files) | Extraction value |
| --- | --- | --- |
| Locale identity | `internal/domain/locale.go`: closed `Locale uint8` enum (DE/EN), parse from BCP 47 primary subtag, `String/Valid/Prefix/Other`, JSON wire format = plain tag | **NONE** — closed enum is a per-app domain decision; appkit uses `language.Tag` at its edges |
| Message lookup | `internal/i18n/i18n.go`: go-i18n v2 bundle, `embed`ed JSON per locale, init-time load, `T/S/TData/SData/TPlural` (ctx-aware + explicit-locale halves for mails) | **HIGH** — ~180 LOC of boilerplate every bilingual service rewrites |
| Fallback chain | locale → canonical → the key itself, with `slog.Warn`/`Error` — missing translations are VISIBLE | HIGH — superb default |
| Negotiation | `cmd/server/locale.go` `withLocale`: URL prefix (`/en`, `/de` alias) > Accept-Language suggestion > default; locale rides ctx; publicPath ctx for the switcher | HIGH — but upgrade the hand-rolled `ParseAcceptLanguage` (see gaps) |
| Slug translation + 308 | route registry translates localized slugs ("/en/imprint" → mux "/impressum"), 308-redirects wrong-locale slugs, query passthrough | **NONE** — depends on the app's route registry; appkit can only offer prefix-strip + ctx |
| SEO | hreflang alternates per route + `x-default` (canonical DE), sitemap `xhtml:link`, NO Accept-Language auto-redirect (soft-launch; Googlebot is en-US), reciprocal alternates only for truly-localized routes | MEDIUM — `Alternates()` helper; the route-aware parts stay app-owned |
| Async artifacts | `Quote.Locale` persisted so confirmation mails follow the journey language, `S(loc, key)` without request ctx | appkit-side: just document the two halves (ctx-aware vs explicit) |
| Formats | `Cents.Format(locale)` money, CLDR plurals via go-i18n `PluralCount` | MEDIUM — x/text `message.Printer` helpers; money types stay consumer-side |
| Guard tests | `guard_test.go`: every key exists in EVERY locale, plural "other" category mandatory, call sites use generated `keys.go` constants only (603 LOC generated by `scripts/gen-i18n-keys.py`, idempotent, fails loudly on drift) | MEDIUM — exportable `MissingIn(tag)` helpers so consumers get parity guards for free |

## Ecosystem research (2026)

- **go-i18n v2.6.1** (Jan 2026, active, MIT) — the consensus message layer:
  embedded message files (JSON/TOML/YAML), CLDR plural rules for 200+
  languages, template data, per-locale `Localizer` with fallback. Criticism:
  no full ICU MessageFormat (gender/select are template-hacky), no
  date/number formatting, silent default-language fallback (sperrmuell's
  visible-fallback chain is the right fix — keep it).
- **golang.org/x/text/language** — the canonical matcher
  (`language.NewMatcher` + `language.ParseAcceptLanguage`, Go blog
  "matchlang"): RFC 4647 with CLDR mutual-intelligibility data
  (`de-AT`→`de`, `pt-PT` vs `pt-BR`, `zh-TW`→`zh-Hant`, `sr-Latn` script
  defaults). Sperrmuell's hand-rolled primary-subtag cut handles `de-AT` but
  would misroute `pt`/`zh` classes. **The framework module must use the
  Matcher** — this is the single biggest correctness upgrade over T49.
- **golang.org/x/text/message + currency** — locale-aware number/currency
  formatting (`message.Printer`, `currency.Symbol`). **No `x/text/date`
  package exists** (printer support "planned") — localized dates stay
  per-locale layout strings server-side or client-side `Intl` (which
  templ-components' relative-time component already does via
  `document.documentElement.lang`).
- Alternatives: `leonelquinteros/gotext` / `vorlif/spreak` (gettext `.po`
  toolchains), `kaptinlin/go-i18n` (full ICU MessageFormat — watcher only).
  None displace go-i18n + x/text for our consumer class.
- **SEO**: subdirectory prefixes + reciprocal hreflang + `x-default`; never
  vary content on Accept-Language alone; 308 (not 307) for locale-slug
  redirects. T49 implements all four correctly — the module encodes them as
  defaults.

## Module sketch (v0.1.0, `/i18n`, package `i18n`)

Composability boundaries: **no core dependency** (realtime/otel/health
pattern — works on any `*http.ServeMux`); deps go-i18n + x/text +
go-error-family. Everything opt-in; nothing joins any default stack
(same ruling as security).

```go
// Negotiation — the HTTP edge.
func NewServer(supported []language.Tag, defaultTag language.Tag, opts ...Option) (*Server, error)
// Option: WithCookie("lang"), WithPrefixRouting(true), WithRedirect308(bool)
func (s *Server) Middleware(next http.Handler) http.Handler
// precedence: URL prefix → cookie → Accept-Language (Matcher) → default;
// injects tag into ctx. Slug translation / route registries stay app-owned.

func FromContext(ctx context.Context) (language.Tag, bool)
func WithContext(ctx context.Context, tag language.Tag) context.Context
func Negotiate(acceptLanguageHeader string, supported []language.Tag, fallback language.Tag) language.Tag
// one-shot for JSON APIs (sperrmuell's "API journey = Accept-Language" P3.2).

// Translation — go-i18n over an fs.FS (embed-friendly).
func NewTranslator(fsys fs.FS, defaultTag language.Tag, opts ...Option) (*Translator, error)
func (t *Translator) T(ctx context.Context, key string, args ...any) string
func (t *Translator) S(tag language.Tag, key string, args ...any) string
func (t *Translator) Plural(tag language.Tag, key string, data any, count any) string
// visible fallback tag → default → key + slog; arg #1 = TemplateData.
func (t *Translator) MissingIn(tag language.Tag) []string // guard-test helper

// SEO + prefix helpers (neutral structs; templ-components maps to SEOAlternate).
func Prefix(tag, canonical language.Tag) string        // "" for canonical, "/en" otherwise
type Alternate struct{ Lang, URL string }
func Alternates(base string, current language.Tag, supported []language.Tag) []Alternate // + x-default
```

Deliberately NOT in v0.1.0 (anti-recommendations, hold the family line):

- **No closed locale enum in appkit** — the artifact-language type
  (sperrmuell's `domain.Locale`, persisted on the quote) is a domain
  decision; appkit speaks `language.Tag` at its edges and consumers convert.
- **No slug-translation router** — needs the app's route registry; the T49
  308/hreflang/sitemap logic stays app code (documented as the cookbook).
- **No Accept-Language auto-redirect** — opt-in `WithRedirect308` at most;
  default is soft-launch (render, don't redirect). SEO + Googlebot posture.
- **No ops-surface translation** — health dashboards, metrics, admin boards
  stay single-language (T49 keeps admin German by decision).
- **No templ/i18n components here** — rendering stays templ-components
  (`Base.Locale` prop + `SEOAlternate` already exist there).

## "and co" — the adjacent surfaces, routed

| Surface | Where it lands | When |
| --- | --- | --- |
| Pretty error pages in the visitor's language | `errorpages.Config.Locale func(*http.Request) language.Tag` (default: `i18n.FromContext`); translated 404/405 copy is a **templ-components** train (errorpage props own the strings) | errorpages next train |
| hreflang alternates in `<head>` | consumers map `i18n.Alternates` → templ-components `SEOAlternate` (type already shipped) | day 1 of module |
| Localized dates | per-locale `time` layouts server-side, or client-side `Intl` via templ-components relative-time (already locale-aware via `documentElement.lang`) | document, don't build |
| Money/numbers | x/text `message.Printer` + `currency` helpers in the module; `Money` types stay in go-composable-business-types | v0.2 candidate |
| Generated keys + parity guards | export `MissingIn`/`AllKeys`; the keys.go generator stays a consumer-side script (T49's is Python, idempotent) | v0.2 candidate |
| Full ICU MessageFormat (gender/select) | watcher: `kaptinlin/go-i18n` | on demand only |
