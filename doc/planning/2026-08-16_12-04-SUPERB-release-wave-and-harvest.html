01Decisions (the three questions, resolved)

Q1 — Push go-appkit now vs batch with v0.3.0: premise was stale. git ls-remote shows master at 0/0 with origin and every existing tag (v0.2.0, cqrs/v0.2.0, docs/v0.2.0, errorpages/v0.1.0) already pushed. All four are fully prepared locally; pushing remains the single user-gated command.

Q2 — Parallel-WIP coordination: freeze code, not docs. The round-3 WIP (still uncommitted) already implements finding 4's replay half (subscribe-first + Last-Event-ID backfill via transport.NewJournalSSEStore) and leaves heartbeat/CORS out by choice; finding 5 (SubscribeAll log-only) is still present in the dirty tree. No cqrs-htmx code is touched by this session. TODO_LIST entries cite the WIP dependency explicitly so the landing review knows what to check.

Q3 — Report home: projects/docs/review/. Sibling streams already use it; the comparison report relocates there with non-destructive annotations (state-of-tree caveat that the original omitted). Findings harvest happens now — TODO_LIST.md is not in the parallel agent's dirty file set, and sequential edits to a shared tree carry no merge risk.

Release-scope decisions from evidence: errorpages v0.1.1 is NOT cut — its only commit since v0.1.0 (83c91bc) is test-only (json/v2 decode in tests). Consumers gain nothing from a tag. docs v0.3.0 is NOT cut — the only drift is a .cqrs-lint.json preset; it is recorded in [Unreleased] instead. No module carries replace directives and no submodule requires an unpublished sibling, so all four tags are independently consumer-valid.
