00Summary

go-appkit composes nine LarsArtmann libraries. This audit compared the touched API surface (exhaustive grep over all 27 non-test and 26 test files) with the full exported capability surface of each pinned version, verified against the local checkouts of the libraries themselves. The good news: nothing is misused, the core paths of every library are wired correctly, and six of nine pins sit on the newest tag. The gaps are concentration, not corrosion: the biggest unused surfaces are httputil.Server (go-appkit still hand-rolls its HTTP server lifecycle on a justification that httputil v1.1.x made obsolete), go-health-dashboard's hardening options (only 2 of ~35 options are ever passed), and go-flightrecorder's operational options (compression, snapshot persistence, metrics hooks).

The bottom line You are using the family well but not to the max. The single highest-leverage change: compose httputil.Server into core's Service instead of owning http.Server directly. The old "no listener access" blocker is gone (ListenerAddr() exists since the v1.1.x line), and that one refactor buys TLS via StartTLS (the deferred Core TLS option), a double-start guard, and ephemeral-port resolution for free. Two version bumps (go-health-dashboard v0.7.0 → v0.8.1, go-error-family v0.10.0 → v0.10.1) are one-line follow-ups.

◆What's already superb

Evidence-backed wins, each verified in code. These are the patterns to keep and the reason the baseline score is solid despite the gaps below.

+

01Findings

Ordered by impact. Every claim cites code or a verified library source location.

Missed opportunity · High impact

httputil.Server unused — Service hand-rolls http.Server on an obsolete justification

service.go (Service owns http.Server + net.Listener directly) · httputil/server.go:162-324 · AGENTS.md Architecture note

httputil v1.1.x Server wraps http.Server with Start/StartTLS (TLSConfig support), a double-start guard returning server.already_started, graceful shutdown, and ListenerAddr() (net.Addr, bool) for ephemeral ports (httputil/server.go:162, :199, :324; CHANGELOG v1.1.0). go-appkit's documented reason for not delegating — "it uses ListenAndServe() internally, no listener access" — no longer holds. Owning the server directly costs appkit: no TLS story (the Core TLS option sits in the deferred register), hand-maintained start/stop state, and duplicate lifecycle logic the family already battle-tested. 

// After: Service composes httputil.Server
type Service struct {
    server  *httputil.Server   // was: http.Server + net.Listener + atomic.Bool
    // Addr() becomes:
}

func (s *Service) Addr() net.Addr {
    a, _ := s.server.ListenerAddr()   // httputil/server.go:324
    return a
}
Recommendation Refactor Service to compose httputil.Server (map the NoTimeout sentinel to zero-timeout fields, keep drain phase semantics in appkit). This unlocks the deferred Core TLS option nearly for free via StartTLS. Verify drain ordering (ready flip → hooks → wait → close) still pins in shutdownlog_test.go.
Missed opportunity · High impact

go-health-dashboard: 2 of ~35 options used, and the pin is two releases behind

health/go.mod (dashboard v0.7.0; local latest v0.8.1) · health/mount.go:82 · example only passes WithTrend/WithMetrics (health/example/main.go:60-61)

The dashboard ships an operator-trust surface go-appkit never turns on: WithShutdownDrain (SSE drain on shutdown — literally appkit's drain story, name-checked in mount.go comments but never passed), WithNonce + RecommendedCSP (the dashboard serves HTML+JS; appkit consumers get no CSP wiring), WithRateLimit, WithIntrospection, WithWebhook (alerting), push modes, grouping/collapse UX. v0.8.0 ("operator trust release", 2026-09-16) adds the failure-evidence truth strip (proven greens vs unproven ones, per the health-washing thesis), WCAG AA status colors, and a consolidated nonce-carried bootstrap — appkit pins v0.7.0 and consumers get none of it.

Recommendation Bump go-health-dashboard to v0.8.1, then extend WithDashboard(opts...) docs/examples to pass WithShutdownDrain, WithNonce + RecommendedCSP, and WithRateLimit in the production-recommended preset (keep zero-options for tests).
Partially used · Medium-high impact

Mounted.Drain stops the probe's refresh loop; go-health built the exact two-phase API for this

health/mount.go:198 (Drain calls m.probe.Shutdown()) · go-health/probe.go:552-558 (MarkShuttingDown)

Probe.Shutdown() marks shutting-down AND kills the background refresh loop (go-health/probe.go, Shutdown doc). Probe.MarkShuttingDown() flips the flag without stopping the loop — its doc describes precisely appkit's drain window: "mark first so load balancers start draining, then call Shutdown after a grace period". Today, a long drain serves a stale cached response and the dashboard trend freezes mid-drain. Readiness still 503s either way, so this is about freshness, not correctness. 

// Before (mount.go:198)
func (m *Mounted) Drain() { m.probe.Shutdown() }

// After: loop keeps refreshing during the drain window
func (m *Mounted) Drain() { m.probe.MarkShuttingDown() }
// Mounted.Shutdown keeps probe.Shutdown() (already does)
Missed opportunity · Medium impact

go-flightrecorder operational options unused: compression, snapshot persistence, metrics

flightrecorder/middleware.go:69-96 · flightrecorderhealth/adapter.go:93-212 · used options: only WithFile/WithWriter/WithMinAge/WithMaxBytes

Both capture paths construct recorders with buffer/file + age/size limits only. Unused: WithCompression (smaller traces for the same capture budget), WithSnapshotDir/WithSnapshotPrefix/WithMaxSnapshots (persistent, rotating snapshots — the middleware currently yields an in-memory artifact a human must fish out via the snapshot endpoint), WithMetrics + MetricsHook (capture counters for the otel module to export), WithLogger, and the OnAll/OnAny trigger combinators (appkit composes trigger logic by hand where the library composes it). 

// Production-recommended recorder preset
rec := fr.New(
    fr.WithSnapshotDir("/var/lib/app/traces"),
    fr.WithMaxSnapshots(5),
    fr.WithCompression(true),
    fr.WithMinAge(30*time.Second), fr.WithMaxBytes(8<<20),
    fr.WithMetrics(hooks), fr.WithLogger(logger),
)
Recommendation Expose a WithRecorderOptions(fr.Option...) passthrough on the flightrecorder middleware and a documented production preset in the README; wire MetricsHook counters into the otel module's meter.
Partially used · Medium impact

go-error-family: Orchestration never used, errorfamilytest unused, a few unclassified sentinels

Orchestration: 0 references repo-wide · errorfamilytest Assert*: 0 uses (tests hand-roll in cqrs/staleness_test.go:136-141) · unclassified: flightrecorder/middleware.go:120-131 (errHTTPStatus fmt sentinel), otel/setup.go:122-155, cqrs/eventservice.go:729

The library offers six families, registries, templates with Fix text, HandleErrorDetailed*, AutoWrap/WrapOnce, an HTTPHandler bridge, and a dedicated errorfamilytest assertion package. go-appkit uses three families and the two re-exports; its own tests hand-roll family assertions the errorfamilytest.AssertFamily/AssertHTTPStatus helpers already provide. Three sites encode meaning in bare sentinels + fmt.Errorf where a classified error would flow through appkit's own HTTPStatus/LogError contract. Also: v0.10.0 is one patch behind v0.10.1 (docs/CI-only, zero API change — trivial bump that carries the conditional-request classification guidance).

Recommendation Bump to go-error-family v0.10.1; switch test assertions to errorfamilytest; classify the errHTTPStatus sentinel as Rejection-with-code and the otel shutdown failures as Infrastructure via WrapInfrastructuref. Adopting Orchestration is optional — appkit has no orchestrator surface yet (not applicable today, revisit with the worker battery).
Partially used · Medium impact

go-health: rich /health payload options and the aggregate package unwired

health/probe.go:60 (only WithCriticalServices wired in prod) · unused: WithBootTime, WithVersion, WithInstanceID, WithLiveThrottle, WithGETOnly, WithAllowedMethods, NewWithDetailedCheck, aggregate/*

go-health can serve a much richer /healthz: boot time, service version, and instance id (battery item F5 "buildinfo" is already routed to TODO_LIST P3 — the library options exist today, only the wiring is missing). WithLiveThrottle and WithGETOnly harden public liveness endpoints; NewWithDetailedCheck + CheckDetail expose per-check diagnostics; the aggregate package (multi-source merge-on-read, worst-of status, source namespacing — shipped through v0.1.3) enables fleet-level views appkit's single-probe NewProbe cannot express.

Recommendation Wire WithVersion/WithBootTime/WithInstanceID from buildinfo into NewProbe defaults (closes F5 with library options, no new schema); document WithGETOnly/WithLiveThrottle as the public exposure preset; note aggregate for multi-instance dashboards.
Partially used · Low-medium impact

go-sse drops are invisible: Broadcaster's WithOnDrop hook unused

realtime/hub.go:51-61 (sets WithBufferSize + OnSubscribe/OnUnsubscribe only) · go-sse/fanout.go:67 (WithOnDrop fires per subscriber whose buffer is full)

The realtime docs correctly state that bursts larger than the subscriber buffer (64) drop events and clients heal via Last-Event-ID reconnect. But the hub never counts the drops: go-sse's WithOnDrop hook exists precisely for this and appkit never sets it, so operators cannot see drop rates (no log line, no metric) even though the recovery contract depends on clients noticing gaps. 

b, _ := sse.NewBroadcaster[sse.Event](store,
    sse.WithBufferSize[sse.Event](opts.BufferSize),
    sse.WithOnDrop[sse.Event](func(evt sse.Event) {
        opts.Logger.Warn("sse subscriber buffer overflow", "event", evt.ID.Get())
        atomic.AddInt64(&dropped, 1)  // surface in Hub.Health()
    }),
)
Duplication · Low impact

errorpages hand-rolls a ResponseRecorder that httputil already ships

errorpages/errorpages.go:206-215 (statusRecorder) · cf. flightrecorder/middleware.go:83 (httputil.NewResponseRecorder)

errorpages carries a local status-capturing ResponseWriter wrapper while flightrecorder (same repo) uses httputil.NewResponseRecorder for the identical job. errorpages deliberately avoids an httputil dependency today, so this is a tradeoff, not a bug — but if the errorpages module ever takes httputil (it already pulls it transitively at v1.1.1 via templ-components' family), the wrapper should go.

Not applicable · verified deliberate

Transitive-only libraries are correctly not force-adopted

go-branded-id v0.5.1 (via go-sse; realtime uses sse.EventID, the branded type) · go-etag v0.3.1 (via httputil) · go-datastar v0.5.0 (via dashboard; realtime duck-types PatchLike, hub.go:109-114)

None of these are underused — they are intentionally indirect, and the duck-typing that keeps go-datastar out of realtime is a documented design decision with tests. One reach item for later: an appkit conditional-GET story (go-etag + go-error-family's new 304/412/428 classification guidance from v0.10.1) is unexplored territory, relevant only once a consumer asks for HTTP caching semantics.
